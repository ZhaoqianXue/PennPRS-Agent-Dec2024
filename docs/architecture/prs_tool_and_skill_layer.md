# PRS Model Skill And Tool Layer

Status: architecture-facing technical note for paper Methods writing.
Last updated: 2026-05-19.
Parent: `docs/architecture/pennprs_agent_paper_framing.md`.

## Purpose

The PRS Model Skill and tool layer is the lower capability layer of PRS Agent. It provides the reusable PRS Model Skill and executable PRS interfaces to the task-specific agent harness layer. It should not be described as a data store inside the agent or as generic conversational memory.

This document exists for manuscript and architecture writing. Do not paste this material into the runtime `src/server/core/skills/prs_model_evaluator/SKILL.md`; that file is the internal implementation of the PRS Model Skill and should remain focused on PGS record evaluation.

## Layer Boundary

The paper-facing architecture is:

```text
LLM orchestration layer
└── Task-specific agent harness layer
    └── PRS Model Skill and tool layer
```

The orchestration layer decides which task-specific route to invoke. The harness layer defines the recommendation procedure and calls the PRS Model Skill and tool layer. The PRS Model Skill and tool layer returns PRS Model Skill guidance, PRS records, evidence artifacts or PennPRS interfaces.

## Contents

The PRS Model Skill and tool layer contains four capability families.

1. **PRS Model Skill.** The PRS Model Skill is the reusable Skill resource for trait-agnostic PGS record evaluation. Its runtime implementation is `prs_model_evaluator`. It encodes endpoint-fidelity checks, metric interpretation, ancestry and transportability considerations, covariate-packaging cautions, publication/context weak signals and uncertainty rules.

2. **PGS retrieval and hydration tools.** These tools search or hydrate PGS Catalog records and return candidate PGS metadata for a normalized phenotype or a selected source phenotype. Candidate PGS sets are outputs of these tools, not top-level architecture components.

3. **PRS evidence tools.** These tools expose evidence channels used by the harnesses, including heritability lookup, genetic correlation estimation and Open Targets evidence. These tools qualify model or source-phenotype plausibility; they do not replace PGS records as recommendation objects.

4. **PennPRS model-training interface.** This interface supports PennPRS-ready training configuration when the user's task is to train a new PRS model rather than to select an existing PGS Catalog score. Downstream validation or risk-analysis planning is generated by PRS Agent after a published PGS model has been selected or a PennPRS-trained model is available.

## Skill Boundary

The PRS Model Skill evaluates the quality of PGS records that are already under consideration. It does not decide which source phenotype is biologically related to the target phenotype. In cross-phenotype transfer, source-phenotype plausibility belongs to the cross-phenotype harness and its evidence tools; within-source or within-bundle PGS quality belongs to the Skill.

For manuscript-facing cross-phenotype writing, genetic-correlation and Open Targets evidence should be described as supporting evidence for the plausibility of a proposed transfer. Do not present a generic biology-retrieval tool as a retained paper-facing evidence channel, and do not imply that these evidence channels replace model-level PGS evaluation.

This boundary should be preserved in Methods writing:

- write that the Skill evaluates PGS record quality;
- write that evidence tools support source-phenotype plausibility and transfer evidence;
- do not write that the Skill alone performs cross-phenotype source selection;
- do not write that PGS Catalog data live inside the Skill.

## Artifacts Produced

The layer can produce or support:

- candidate PGS model tables;
- hydrated PGS records;
- heritability evidence;
- genetic-correlation evidence;
- Open Targets evidence;
- source-phenotype evidence summaries;
- PennPRS training configurations;
- validation and downstream-analysis inputs.

These artifacts are consumed by the task-specific agent harness layer, the PennPRS model-training interface or downstream analysis-planning steps and may later be represented in recommendation records, model-landscape views, benchmark traces or exported reports.

## Methods Wording

Recommended wording:

> The PRS Model Skill and tool layer exposes the reusable Skill guidance and executable interfaces used by the harnesses, including the PRS Model Skill for trait-agnostic PGS record evaluation, PGS Catalog retrieval and hydration, PRS evidence tools and PennPRS analysis interfaces.

Avoid:

- `evidence-and-skill substrate`;
- `foundation-model controller`;
- `central PRS agent`;
- statements implying that PGS data are stored inside the agent;
- statements implying that the PRS Model Skill performs source-phenotype discovery by itself.
