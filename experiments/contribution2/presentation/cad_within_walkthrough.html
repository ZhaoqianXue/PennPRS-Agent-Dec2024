STEP 03 · RECORD SELECT 05

DETERMINISTIC · 代码
11 → 1

条记录 → 一条代表性记录

代码 · 非 LLM

PGS003725 有 11 条 performance record（不同队列 / 祖先）。系统先用确定性规则挑出唯一一条 —— 这一步不是 LLM：

A优先最高结果的 European 验证记录，否则取整体最高
B“最高结果”先认 PRS-only / 协变量回归后的指标，都没有才退回 full-model
C绝不跨记录混字段（不会把 A 记录的 AUC 配 B 记录的样本量）

这就是你们熟悉的“多个验证估计该信哪个”问题 —— 这里由代码定死，把判断负担留给后面的 LLM。

STEP 04 · AGENT VIEW 06

字段 → Agent 视图　serialization

LLM READS TEXT, NOT A DATAFRAME

关键事实（讲给不懂 LLM 的人）

1LLM 只读文本，不能像查数据库那样中途 SELECT 字段
2所以要先把 81×字段“打印成一份卷宗”喂进去
3每个候选组织成 7 个带标签的小节（trait / performance / validation / training-ancestry / method / publication / variants）

类比 · 给评审专家一份 dossier

他只能基于纸面信息判断。由此推出两个必须接受的事实：

① 没被序列化进来的字段，模型根本看不到。

② 这份卷宗的“排版方式”本身是可设计的 —— 这就引出 Skill。

WHAT · DEFINITION 07

What is the PRS Skill

SKILL.md + 8 REFERENCE FILES

不是评分公式、不是回归、不是硬过滤器。

Skill 是一份注入 Agent 卷宗、按字段组织的“专家阅读手册”：逐字段告诉模型这个字段对真实世界 PRS 质量意味着什么、该不该信。

How the Skill reads each field

SIGNAL / NOISE / MIXED
§字段判定Skill 的核心规则（PGS 语言）

Skill 的作用 = 告诉 Agent 哪些字段是信号、哪些是噪声，以及字段冲突时怎么裁决。规则是“文字建议”，不是权重数字。

HOW · DECISIVE RULE §2 09

胜负手 · effect sizes 规则

reference / §2

“候选只报 effect sizes 而无 AUROC/R² 时，把效应量当作支持性 PRS 质量信号；OR per SD 是比自报 AUC 更强的真实表现预测因子；per-SD OR/HR ≥ 1.5 即为有力证据。不要因为指标类型就自动加分。”

应用到 PGS003725

OR per SD 2.14、HR 1.75（均 ≥1.5），但 没有 PRS-only AUC/R² → Skill 判定：这是强判别证据。

避开的陷阱 · PGS000013

有干净的显式 PRS-only R²=0.04，但更老、无更强判别信号。朴素直觉“显式指标更安全”会选它 —— 而它实测 rank 27/81。

WHY · NOT A FORMULA 10

为什么是 Skill，不是评分公式

LLM-LED · TRAIT-AGNOSTIC · ADVISORY

你们一定会问：这些字段，为什么不直接拟合一个加权评分 / 回归？四条理由：

1指标跨记录不可比 → 根本没有干净的数值特征可喂回归
2规则之间会冲突、无固定优先级 → 需要逐案判断，不是一个固定权重向量
3trait-agnostic（规则不出现任何病名）→ 泛化到没见过的病，不做 per-disease 调参 —— 即你们最熟的“避免 overfitting”
4advisory / 可推翻 → 对 PGS Catalog 脏数据稳健

一句话：硬编码评分 = 对当前疾病集过拟合；Skill = 把领域先验写成可泛化、可逐案权衡的判断规则。
